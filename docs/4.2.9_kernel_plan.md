# Plan: Port Linux 4.2.9 to Casio Cassiopeia BE-300

## Context

The BE-300 uses a NEC VR4131 CPU (µPD30131) with a VRC4173 companion chip (µPD31173) for peripherals. Linux 4.2.9 already has mature VR4131 support in mainline — CPU detection, BCU, CMU, ICU, GIU, PMU, RTC, SIU, and multiple reference boards (TANBAC TB022X, ZAO Capcella). The task is to add the BE300 as a new board and produce a `vmlinux` that boots to userspace in the `bin/be300` emulator.

No single source tree, patch set, or code overlay is the single source of truth. All sources (2.4.18 tree, kernel-2.6/kernel-unstable-2.6.x overlays, patches, hardware docs, boot logs, emulator behavior) must be cross-referenced.

**Key hardware facts** (cross-referenced from docs/hardware.txt, docs/hw_notes.txt, VR4131 manual, VRC4173 manual, boot logs, source overlays):
- CPU: VR4131 at 0xAF000000+ (Type 2 peripherals), VR4131 SIU at 0xAF000800
- Companion chip at 0xAA000000+ — serial UART at 0xAA008680 (NOT the VR4131's SIU), video RAM at 0xAA200000
- I/O port base: 0xAA00C000
- RAM: 16 MB at physical 0x00000000
- Display: 240x320, 16bpp, stride 512 bytes (xres_virtual=256). Per hardware.txt: RGB565 (bits 15-11=red, 10-5=green, 4-0=blue). sfb.c codes RGB555 (green.length=5). Emulator supports both via `--sfb-5bit-green` flag.
- Companion chip UART: 4-byte register spacing, register layout compatible with serial_reg.h names but it is a NEC D89041F1001, NOT an 8250
- serial_be300 driver is incomplete

**Emulator constraints** (`bin/be300 --help`):
- `--kernel <vmlinux>` loads ELF directly
- `--cmdline <string>` passes bootinfo (fw_arg0/fw_arg1)
- No `--initrd` flag — initramfs must be built into vmlinux
- `--sfb-5bit-green` for sfb.c's 5-bit green format
- `--sdram <MB>` defaults to 16

**What 4.2.9 already provides** (verified in extracted tree):
- `arch/mips/vr41xx/common/init.c`: `prom_init()` (parses fw_arg0/fw_arg1 → arcs_cmdline), `plat_mem_setup()` (inits iomem, calls vr41xx_siu_setup), `prom_free_prom_memory()`
- `arch/mips/vr41xx/common/bcu.c`: Clock calculation for VR4131 (PClock = 18.432MHz × 108 / CLKSP)
- Full ICU, CMU, GIU, PMU, RTC, SIU, IRQ support
- Board pattern is minimal: just `arch_initcall` with `set_io_port_base()` + ioport_resource (see casio-e55/setup.c: 10 lines)
- Memory specified via `mem=` kernel command line param (early_param handler in setup.c)
- `drivers/video/fbdev/simplefb.c`: Supports `"r5g6b5"` and `"x1r5g5b5"` via platform device
- `SYS_HAS_EARLY_PRINTK` not selected for VR41xx by default

## Step 1: Create `build_be300_kernel.sh`

New build script. Sequence:
1. Download & extract linux-4.2.9-patched.tar.xz (same as build_tcl_kernel.sh)
2. Apply GCC 10+/11+ fixes (yylloc, log2.h, -Werror)
3. Inject BE300 board support files into the kernel tree (Steps 2-4)
4. Build BusyBox + initramfs directory (reuse existing scripts)
5. Copy defconfig, set `CONFIG_INITRAMFS_SOURCE` to the rootfs directory path
6. Build vmlinux

**File**: `build_be300_kernel.sh`

## Step 2: Create BE300 Board Support

Create `arch/mips/vr41xx/casio-be300/` with two files:

### 2a. `setup.c` — Board setup (arch_initcall)

Following the casio-e55 pattern (10 lines). The companion chip I/O space starts at physical 0x0A00C000:

```c
#include <linux/init.h>
#include <linux/ioport.h>
#include <linux/platform_device.h>
#include <linux/platform_data/simplefb.h>
#include <asm/io.h>

#define BE300_ISA_IO_BASE    0x0a00c000
#define BE300_ISA_IO_SIZE    0x05ff4000
#define BE300_IO_PORT_BASE   KSEG1ADDR(BE300_ISA_IO_BASE)

static struct resource simplefb_resources[] = {
    {
        .start = 0x0a200000,   /* physical address of VRAM */
        .end   = 0x0a200000 + (320 * 256 * 2) - 1,
        .flags = IORESOURCE_MEM,
    },
};

static struct simplefb_platform_data simplefb_pdata = {
    .width  = 240,
    .height = 320,
    .stride = 256 * 2,
    .format = "r5g6b5",    /* per hardware.txt: RGB565 */
};

static struct platform_device simplefb_device = {
    .name          = "simple-framebuffer",
    .id            = 0,
    .dev.platform_data = &simplefb_pdata,
    .num_resources = ARRAY_SIZE(simplefb_resources),
    .resource      = simplefb_resources,
};

static int __init casio_be300_setup(void)
{
    set_io_port_base(BE300_IO_PORT_BASE);
    ioport_resource.start = 0;
    ioport_resource.end = BE300_ISA_IO_SIZE - 1;

    platform_device_register(&simplefb_device);
    return 0;
}
arch_initcall(casio_be300_setup);
```

**Note on framebuffer format**: hardware.txt says RGB565 (6-bit green). sfb.c from the 2.6 overlay uses 5-bit green. The emulator's `--sfb-5bit-green` flag exists specifically for this discrepancy. Start with `"r5g6b5"` (what the hardware docs say), test, and try `"x1r5g5b5"` if colors are wrong.

**Note on simplefb resource address**: Use physical address 0x0A200000 (not 0xAA200000). The simplefb driver calls `ioremap_wc()` which expects a physical address. KSEG1 mapping (0xAA200000) is a virtual address.

### 2b. `Makefile`

```makefile
obj-y := setup.o
```

### 2c. `prom_putchar` for early printk (optional, in setup.c or separate file)

Add `prom_putchar()` to enable `CONFIG_EARLY_PRINTK`. The companion chip UART at 0xAA008680 uses 4-byte register spacing. Based on cross-referencing debug.c, v2.6.diff, serial_be300.c/h, and hw_notes.txt:

```c
void prom_putchar(char c)
{
    volatile u8 *uart = (volatile u8 *)KSEG1ADDR(0x0A008680);
    while ((uart[0x14] & 0x20) == 0)  /* LSR offset 0x14, THRE bit 5 */
        ;
    uart[0x00] = c;  /* THR offset 0x00 */
}
```

## Step 3: Wire into Kconfig & Build System

### 3a. `arch/mips/vr41xx/Kconfig` — Add inside the `choice` block:

```kconfig
config CASIO_BE300
    bool "CASIO CASSIOPEIA BE-300"
    select CEVT_R4K
    select CSRC_R4K
    select DMA_NONCOHERENT
    select IRQ_MIPS_CPU
    select ISA
    select SYS_SUPPORTS_32BIT_KERNEL
    select SYS_SUPPORTS_LITTLE_ENDIAN
    select SYS_HAS_EARLY_PRINTK
```

### 3b. `arch/mips/vr41xx/Platform` — Add:

```
platform-$(CONFIG_CASIO_BE300)  += vr41xx/casio-be300/
load-$(CONFIG_CASIO_BE300)      += 0xffffffff80004000
```

Load address 0x80004000 matches the other pocket devices (E55, WorkPad). Cross-reference with emulator behavior — if it loads the ELF at the entry point, this should work.

## Step 4: VR4131 Cache Bug Patches

The VR4131 has a known cache instruction bug (Hit_Writeback_Inv_D must be split into separate writeback + invalidate). Two patches exist:

- `patches/vr4131_cachebug_fix.patch` — splits cache ops in `r4kcache.h`
- `patches/vr4131_no_change_cache_line.patch` — disables config register workaround in `c-r4k.c`

These target 2.6.x file paths. For 4.2.9:
- `r4kcache.h` is now at `arch/mips/include/asm/r4kcache.h`
- `c-r4k.c` is still at `arch/mips/mm/c-r4k.c`
- The macro structure has evolved

**Strategy**: Try without cache patches first (the emulator may not exhibit the bug). If cache-related crashes occur, adapt the patches to 4.2.9 code.

## Step 5: Create BE300 Defconfig

Create `configs/be300_defconfig` and copy to `arch/mips/configs/` at build time.

```
# Platform
CONFIG_MACH_VR41XX=y
CONFIG_CASIO_BE300=y

# Console
CONFIG_EARLY_PRINTK=y
CONFIG_VT=y
CONFIG_VT_CONSOLE=y
CONFIG_DUMMY_CONSOLE=y

# Framebuffer (simplefb for display)
CONFIG_FB=y
CONFIG_FB_SIMPLE=y
CONFIG_FRAMEBUFFER_CONSOLE=y
CONFIG_FONTS=y
CONFIG_FONT_8x8=y
CONFIG_FONT_8x16=y

# Serial: BE300 companion chip UART is NOT 8250
# CONFIG_SERIAL_8250 is not set

# Root filesystem (built-in initramfs)
CONFIG_BLK_DEV_INITRD=y
CONFIG_INITRAMFS_SOURCE="<path set by build script>"
CONFIG_INITRAMFS_COMPRESSION_GZIP=y
CONFIG_RD_GZIP=y

# Minimal required
CONFIG_BINFMT_ELF=y
CONFIG_BINFMT_SCRIPT=y
CONFIG_PROC_FS=y
CONFIG_SYSFS=y
CONFIG_TMPFS=y
CONFIG_DEVTMPFS=y
CONFIG_DEVTMPFS_MOUNT=y
CONFIG_EXT2_FS=y

# Block device for ramdisk
CONFIG_BLK_DEV_RAM=y
CONFIG_BLK_DEV_RAM_SIZE=4096

# Disable unneeded
# CONFIG_MODULES is not set
# CONFIG_NET is not set
# CONFIG_SOUND is not set
# CONFIG_USB_SUPPORT is not set
# CONFIG_PCI is not set
# CONFIG_IDE is not set
# CONFIG_SCSI is not set
# CONFIG_SWAP is not set
# CONFIG_MTD is not set
```

Start with an existing VR41xx defconfig (e.g., from `make ARCH=mips vr41xx_defconfig` or similar), then customize. Run `make olddefconfig` to resolve dependencies.

## Step 6: Build Initramfs

1. Build BusyBox using existing `build_busybox.sh`
2. Create rootfs directory using logic from `create_initramfs.sh` (but NOT the cpio/gzip step — just the directory with /init, /bin, /etc, etc.)
3. Set `CONFIG_INITRAMFS_SOURCE` in the defconfig to point to this directory
4. The kernel build will embed the initramfs into vmlinux

## Step 7: Build & Test

```bash
# Inside Docker container:
./build_be300_kernel.sh

# On macOS host:
./bin/be300 --kernel linux-4.2.9/vmlinux --cmdline "mem=16M console=tty0 earlyprintk"

# If framebuffer colors are wrong, try the 5-bit green mode:
./bin/be300 --kernel linux-4.2.9/vmlinux --cmdline "mem=16M console=tty0 earlyprintk" --sfb-5bit-green
```

`mem=16M` is needed because the common VR41xx `prom_init()` doesn't add memory regions.

## Iterative Approach

1. **First pass**: Board setup.c + prom_putchar + simplefb + defconfig. Boot with `console=tty0 earlyprintk mem=16M`. Goal: kernel boot messages on framebuffer, reach BusyBox shell.
2. **Second pass**: Debug using `--log-mmio` and `--trace` if needed. Compare register accesses to known-good 2.4/2.6 kernels.
3. **Third pass**: Apply VR4131 cache patches if cache-related issues arise. Tune .config for 16 MB RAM.
4. **If simplefb doesn't work**: Fall back to porting sfb.c (adapt for 4.2.9 fb API changes: remove fb_cursor, fix fb_mmap signature, FBINFO_DEFAULT).
